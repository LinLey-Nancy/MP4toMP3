# 设计方案：MP4toMP3 增加语音转写与说话人分离

- 日期：2026-10-10
- 状态：待评审
- 范围：在现有「视频批量转 MP3」工具上，增加本地语音转文字 + 说话人区分能力（会议记录场景）

## 1. 背景与目标

现有工具（`main.py`，单文件 tkinter）用 ffmpeg 批量把视频转成 MP3。用户希望转完 MP3 后进一步把音频识别成文字，并区分不同讲话人（如会议记录）。

硬性约束：

- 纯本地运行，不依赖任何云端服务
- 便携（可 U 盘拷贝）、轻量
- 普通办公本（纯 CPU）与 NVIDIA 显卡机器都要能跑，自动适配
- 音频主要是中文
- 输出：带时间戳 + 说话人标签的文本

确认的决策（来自需求问答）：

| 问题 | 结论 |
|---|---|
| 硬件 | 纯 CPU 与 N 卡都兼容，自动切换 |
| 语言 | 主要中文 |
| 模型分发 | 两种发行包：迷你包（首启下载模型）+ 全量包（内置模型） |
| 输出 | 带说话人标签与时间戳的文本 |
| 技术路线 | A：faster-whisper 转写 + sherpa-onnx 说话人分离 |

## 2. 技术选型

| 模块 | 选择 | 理由 |
|---|---|---|
| 转写 | faster-whisper（CTranslate2，int8 量化） | CPU 上约 4 倍于原版 whisper；检测到 N 卡自动切 CUDA；成熟稳定 |
| 说话人分离 | sherpa-onnx 分离流水线（pyannote-segmentation-3.0 + 3dspeaker 声纹聚类） | 全 ONNX，模型合计约 35MB，纯 CPU 高速，不依赖 PyTorch |
| 打包 | PyInstaller onedir，模型外置 `models/` 目录 | 便于换模型/升级；两种发行包只是 `models/` 有无的区别 |

否决项：

- 全 sherpa-onnx 一体化（路线 B）：体积最小但 whisper ONNX 导出版社区验证少，VAD/标点需自拼，风险高
- FunASR 全家桶（路线 C）：中文效果最强但依赖 PyTorch，打包 3GB+，与便携轻量冲突

## 3. 架构

```
main.py                # 现有 GUI，最小改动（见 §5）
transcribe/
  pipeline.py          # 编排：逐文件 转写→分离→对齐→写 txt
  asr.py               # faster-whisper 封装（设备自动选择、VAD）
  diarize.py           # sherpa-onnx 分离封装（聚类，支持指定人数）
  align.py             # 时间戳重叠对齐：whisper 段 → 说话人标签，相邻同人合并
  models.py            # 模型检测 / 下载（ModelScope 镜像）/ sha256 校验 / 断点续传
models/                # 外置模型目录（不进 exe）
temp/                  # 临时 16k 单声道 wav，启动时清理残留
```

### 数据流

```
视频 ──ffmpeg(现有)──▶ MP3 ──▶ mp3_output/
  └─ffmpeg 同步输出 16k 单声道临时 wav ──▶ sherpa-onnx 分离（快，先跑）
                                        └─▶ faster-whisper 转写
                                               └─▶ 对齐合并 ──▶ transcript_output/<同名>.txt
```

设计要点：

- 转 MP3 与转写解耦：MP3 永远产出；未勾选转写或模型缺失时行为与现在完全一致
- 每文件串行（分离→转写→对齐），CPU 机器上避免争抢；文件间沿用现有 worker 线程 + 队列模式
- 对齐策略：按时间段重叠占比把 whisper 段分配给说话人；相邻同说话人段合并；标点用 whisper 自带输出

## 4. 模型管理

| 用途 | 模型 | 大小 | 来源 |
|---|---|---|---|
| 转写（默认） | whisper-small (int8) | ~250MB | HuggingFace |
| 转写（高精度可选） | whisper-large-v3-turbo (int8) | ~800MB | HuggingFace |
| 语音分割 | pyannote-segmentation-3.0 (ONNX) | ~6MB | sherpa-onnx 发布页 |
| 声纹嵌入 | 3dspeaker-speech-eresnet (ONNX) | ~28MB | ModelScope |

- 迷你包：首启检测 `models/` 缺失 → 弹窗确认 → 后台下载（ModelScope 镜像，国内免梯），进度条 + sha256 校验 + 断点续传；下载完成后纯离线
- 全量包：`models/` 随包内置
- 设置项可切换 small ↔ turbo，按需下载，不强制全下
- 默认 small；会议纪要等准确度敏感场景建议 turbo

体积估算：运行时 + 依赖约 300MB；全量包（small）约 600MB，（turbo）约 1.1GB。

## 5. UI 改动（最小侵入）

主窗口只加两个控件，不动现有转换流程：

1. 勾选框「转写文字（识别说话人）」，默认关；勾选后 MP3 转换完成自动进入转写阶段
2. 下拉「说话人数」：自动检测 / 2 / 3 / 4 / 5 人；已知人数可明显提高聚类准确度

转写阶段复用现有 Progressbar，标签显示「转写 i/N：文件名」。完成后弹窗提示输出目录。

输出示例（`transcript_output/周会.txt`）：

```
[00:00:02] 说话人1: 我们先过一下上周的进度。
[00:00:15] 说话人2: 客户端那边联调基本完成了……
```

## 6. 错误处理与边界

- 模型缺失且用户拒绝下载 → 只做 MP3 转换，原功能不受影响
- 音频无人声 / 单人说话 → 正常输出，说话人标「说话人1」
- 单文件转写失败 → 记日志、跳过，不阻塞队列（沿用现有容错风格）
- 中途关窗 → 沿用现有退出确认；`temp/` 临时 wav 启动时清理

## 7. 验证

- 测试音频 3 段：单人讲话、双人对话、4 人会议（各 1~3 分钟）
- 人工核对：说话人切换点误差、中文错字率
- 纯 CPU 与 N 卡环境各跑一遍，确认设备自动切换
- 迷你包在断网虚拟机验证「下载 → 离线可用」闭环
